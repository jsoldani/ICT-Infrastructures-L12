# Docker Demos: Compose and Stack

This repository contains two complementary Docker demonstrations designed for a hands-on lecture on **Docker, Docker Compose, Docker Swarm, and Docker Stack**.

The demonstrations use the same simple database-backed web application so that students can focus on the differences between the deployment approaches rather than learning unrelated examples.

## Repository structure

```text
.
├── README.md
├── compose-demo/
│   ├── README.md
│   ├── compose.yaml
│   └── web/
│       ├── Dockerfile
│       ├── requirements.txt
│       └── app.py
└── stack-demo/
    ├── README.md
    ├── compose.yaml
    └── web/
        ├── Dockerfile
        ├── requirements.txt
        └── app.py
```

The two demos are intentionally similar:

- `compose-demo` shows how to define and run a **multi-container application with Docker Compose**.
- `stack-demo` shows how the same application can be deployed as a **Docker Stack on a Docker Swarm**.

The second demo extends the first with concepts such as service replicas, desired state, scaling, self-healing, and service updates.

# Application architecture

Both demos use a small web application composed of two services:

```text
                         Docker network
                   ┌─────────────────────────┐
                   │                         │
Browser            │       web service       │
   │               │   Python application    │
   │ :8080         │                         │
   └──────────────►│       :8080             │
                   │            │            │
                   │            │ db:5432    │
                   │            ▼            │
                   │       db service        │
                   │       PostgreSQL        │
                   │            │            │
                   │            ▼            │
                   │       dbdata volume     │
                   └─────────────────────────┘
```

The **web service**:

- runs a small Python HTTP server;
- listens on port `8080`;
- connects to PostgreSQL;
- creates the `visits` table when necessary;
- records every request;
- retrieves and displays the stored visits;
- displays its own container hostname.

The **database service**:

- runs PostgreSQL;
- stores the visits generated by the web application;
- uses a named Docker volume for persistent storage.

The application therefore provides a concrete example of a common architecture:

```text
Client
  │
  ▼
Web application
  │
  ▼
Database
  │
  ▼
Persistent storage
```

# Why use the same application in both demos?

The goal is to make the transition from Compose to Stack explicit.

In the Compose demo, students learn how to manage:

- multiple containers;
- service-to-service networking;
- service names as DNS names;
- environment variables;
- persistent volumes;
- application startup and shutdown.

In the Stack demo, these concepts remain, but Docker Swarm adds:

- services and tasks;
- replicas;
- cluster-level scheduling;
- desired-state management;
- scaling;
- self-healing;
- service updates.

Thus the conceptual progression is:

```text
docker run
     │
     ▼
single container
     │
     ▼
Docker Compose
     │
     ▼
multi-container application
     │
     ▼
Docker Swarm
     │
     ▼
cluster
     │
     ▼
Docker Stack
     │
     ▼
multi-service cluster application
```

# Compose demo

The `compose-demo` directory contains the development-oriented version of the application.

Docker Compose describes the application declaratively in `compose.yaml`:

```text
web
 │
 └── db
```

The application can be started with:

```bash
docker compose up --build
```

The demo focuses on:

- defining multiple services;
- building an application image;
- running PostgreSQL;
- connecting services through a Docker network;
- using environment variables;
- persisting database data with a named volume.

See [`compose-demo/README.md`](compose-demo/README.md) for the complete instructions.

# Stack demo

The `stack-demo` directory contains the Swarm-oriented version.

The application is deployed using:

```bash
docker stack deploy -c compose.yaml demo
```

The web service is configured with multiple replicas:

```yaml
deploy:
  replicas: 3
```

This makes it possible to demonstrate:

```text
                 Stack
                   │
             ┌─────┴─────┐
             │            │
          web service   db service
             │            │
        ┌────┼────┐       │
        ▼    ▼    ▼       ▼
      task task task     task
       │    │    │        │
       ▼    ▼    ▼        ▼
      web  web  web       db
```

The demo focuses on:

- Swarm initialization;
- Docker services;
- replicas;
- tasks;
- scaling;
- desired state;
- self-healing;
- image versioning;
- service updates;
- the distinction between stateless and stateful services.

See [`stack-demo/README.md`](stack-demo/README.md) for the complete instructions.

# Main architectural concepts

## Service-name networking

The web application connects to PostgreSQL using:

```text
db
```

rather than a hard-coded IP address.

Docker provides service/container name resolution on the application network.

The database is therefore accessed as:

```text
db:5432
```

This remains true in both demonstrations.

## Persistent storage

PostgreSQL stores its data in:

```text
dbdata
```

The volume means that removing and recreating the database container does not automatically remove the database contents.

This also illustrates an important distinction:

> Containers are disposable; application data may need to survive the lifecycle of individual containers.

## Stateless and stateful components

The web service is designed to be effectively stateless: any web replica can process a request because the persistent data resides in PostgreSQL.

The database is stateful and is therefore deliberately configured as a single replica in the educational Stack example.

This distinction is particularly important when discussing orchestration.

# Intended teaching progression

The repository is designed to support the following sequence during a lecture:

1. Build and run a Docker image.
2. Introduce a multi-container application.
3. Run the application with Docker Compose.
4. Inspect services, networks, logs, and volumes.
5. Introduce Docker Swarm.
6. Deploy the same application as a Docker Stack.
7. Inspect services and tasks.
8. Scale the web service.
9. Demonstrate self-healing by removing a web container.
10. Build and deploy a new image version.
11. Update the Swarm service.

The central message is that **Docker Compose and Docker Stack use similar application-level concepts, but Stack adds Swarm orchestration capabilities**.

# Requirements

The demos require:

- Docker Engine or Docker Desktop;
- Docker CLI;
- Docker Compose support (`docker compose`);
- Internet access to pull the PostgreSQL base image and, for the Stack demo, the application image from a registry.

For the Stack demo, Docker Swarm support is required. Docker Desktop and Docker Engine include the necessary functionality.

---

# Educational scope

These projects are intentionally small and are designed for teaching rather than production deployment.

In particular:

- the PostgreSQL password is deliberately simple;
- secrets management is not demonstrated;
- PostgreSQL replication is not configured;
- the Python HTTP server is intentionally minimal;
- the web service is not hardened for production;
- the Stack example uses a single database replica.

The purpose is to expose Docker concepts with the smallest application that can demonstrate them clearly.
